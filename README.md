# Forte Vision — контроль кассовой дисциплины по видео

**Команда Quanta · ForteBank Datathon 26**

Локальный AI-сервис: принимает видео с потолочной камеры кассы и сообщает, есть ли визуальные признаки
нарушения. Для каждого найденного события показывает **тип, таймкод, 1–3 кадра-доказательства, описание
того, что видно, и пункт нормы НБРК**. Все модели работают внутри сервиса, облачные AI-API не используются.

> Результат — подсказка для проверяющего, а не юридическое заключение. Каждое описание заканчивается
> фразой «Требуется проверка человеком».

## 2. Быстрый старт

**Требования:** Windows или Linux, NVIDIA GPU с 24 ГБ видеопамяти (Qwen2.5-VL-7B в bf16; при 16 ГБ —
`VLM_QUANT=4bit`, но пороги откалиброваны без квантования), Python 3.11, CUDA 12.x.

```powershell
# 1. Зависимости
pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt -r requirements-ml.txt

# 2. Веса моделей (один раз, дальше интернет не нужен)
huggingface-cli download Qwen/Qwen2.5-VL-7B-Instruct --local-dir C:\models\qwen2.5-vl-7b
huggingface-cli download google/owlv2-base-patch16-ensemble --local-dir C:\models\owlv2-base

# 3. Настройки
copy .env.example .env
notepad .env          # API_KEY, VLM_PATH, OWL_PATH, PIPELINE=vlm, STATE_DESCRIBE=0
python -c "import secrets; print(secrets.token_urlsafe(32))"   # сгенерировать API_KEY

# 4. Запуск (или двойной клик run.bat)
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Через ~1 минуту (загрузка моделей) в окне появится `[service] PIPELINE=vlm ... REAL MODELS` и
`Application startup complete`. Страница: http://localhost:8000.

**Публичный адрес** (во втором окне, сервис должен работать):
```powershell
ngrok http --url=<ваш-домен>.ngrok-free.dev 8000
```

### Настройки `.env`

| Переменная | Значение |
|---|---|
| `API_KEY` | ключ для жюри; без верного ключа API отвечает 401 |
| `PIPELINE` | `vlm` — реальные модели; `mock` — заглушка без GPU |
| `VLM_PATH`, `OWL_PATH` | локальные папки с весами |
| `STATE_DESCRIBE` | `0` — описание только по сработавшему правилу (рекомендуется); `1` — добавить фразу Qwen |
| `VLM_MAX_PIXELS`, `FACT_FPS`, `TILE_EVERY`, `DETS` | **не менять**: пороги откалиброваны при этих значениях, иначе сервис откажется стартовать |
| `MAX_UPLOAD_MB` | лимит размера файла (300) |

## 3. Как пользоваться

1. Откройте веб-интерфейс и выберите видео `.mov`.
2. Нажмите «Начать проверку» — страница показывает статус обработки.
3. Результат: **«Нарушение не обнаружено»** или **«Обнаружены признаки возможных нарушений»**. Для каждого
   события — тип, таймкод (клик переводит видео к моменту), описание, документ и пункт нормы, кадры.
4. Отчёт можно распечатать / сохранить в PDF или скачать JSON.

Время обработки на одной GPU: видео 20 с — около 25 с; самое длинное видео датасета (143 с) — 158 с
(лимит 300 с). Видео обрабатываются по очереди.

## 4. API

Доступ по ключу в заголовке `X-API-Key`. Работа в два шага.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/v1/analyze` | загрузить видео (поле `file`) → `{"job_id", "status": "processing"}` |
| GET | `/api/v1/jobs/{job_id}` | статус `processing` / `done` / `failed` и результат |
| GET | `/health` | проверка, что сервис жив |

```bash
curl -X POST https://<адрес>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
curl https://<адрес>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

Ответ после обработки:
```json
{
  "job_id": "61147b1ecbf5",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Оставление наличных денег без присмотра",
      "timecode_sec": 11.0,
      "description": "С 11 с на столе лежат наличные: кассир уходит от рабочего места, наличные остаются на столе без присмотра … Норма: … п. 20 … Требуется проверка человеком.",
```

## 5. Архитектура

```
                      ┌──────────────────────────┐
                      │ OWLv2 — «что и где»       │──── зона двери ───► Дверь: конец ≠ начало ─┐
 Видео .mov ─► кадры ─┤ люди, деньги, сумки,      │                     (пиксели, без модели)  │
   1 кадр/с,          │ чашки; зоны сейфа, двери, │                                            ▼
   без сжатия         │ стола; тайлы SAHI         │──── объекты ──► State engine ──────────► Judge ─► Отчёт
                      └──────────────────────────┘                 сигнал сверх фона       порог   тип, таймкод,
                      ┌──────────────────────────┐                 своего видео;           ▲       кадры, пункт
                      │ Qwen2.5-VL-7B             │──── факты ────► условия нормы           │       НБРК → UI / API
                      │ 14 вопросов да/нет на кадр│                 держатся N секунд       │
                      └──────────────────────────┘                                          │
                                         Офлайн: пороги по 40 обучающим видео, заморожены ──┘
```

1. **Кадры** — 1 кадр в секунду в исходном разрешении (464×848 не уменьшается).
2. **OWLv2** (open-vocabulary детектор) находит по текстовым запросам людей, банкноты, сумки, чашки и
   фиксированные зоны (сейф, дверь, стол, ноутбук). Мелкие объекты ищутся по тайлам (SAHI); люди
   связываются в треки.
3. **Qwen2.5-VL-7B** отвечает на каждом кадре на 14 вопросов да/нет («кассир на рабочем месте?»,
   «на столе лежат наличные?», «клиент в помещении?» …). Берётся **вероятность токена «да»** — число
   0…1, а не сгенерированный текст.
4. **State engine** превращает числа в состояния во времени и проверяет правила.
5. **Дверь** — отдельная проверка без нейросети: область двери в конце видео сравнивается с началом
   (кадры, где в проёме человек, пропускаются).
6. **Judge** сравнивает оценку каждого правила с замороженным порогом и собирает ответ: тип, таймкод,
   кадры, описание, норма из справочника (никогда не из текста модели).

Модели только **описывают кадр**. Вердикт выносит прозрачное правило, которое можно объяснить проверяющему.

## 6. Как принимается решение

1. **Сигнал относительно своего видео.** Значение минус обычный уровень этого же ролика
   (20-й перцентиль). Другой ракурс или свет сдвигают фон, а не скачок.
2. **Состояние держится N секунд.** Минимум за окно: условие должно выполняться на каждом кадре окна,
   шум одного кадра не проходит. Оценка правила = минимум по его условиям (логическое «И»).
   Пример: «наличные без присмотра» = min(деньги на столе ≥ 3 с, кассира нет ≥ 2 с).
3. **Порог — выше любой нормы.** Порог типа = самая высокая оценка среди чистых обучающих видео + запас
   (конформный тест на выброс, Bates et al., 2023). Пороги посчитаны один раз, хранятся в
   `catalog/judge_thresholds.json` и на новых видео **не меняются**.
4. **Таймкод** — первая секунда, когда выполнены все условия правила; кадры-доказательства берутся из
   этого фрагмента.

## 7. Модели и почему именно они

| Модель | Лицензия | Роль | Почему |
|---|---|---|---|
| Qwen2.5-VL-7B-Instruct | Apache-2.0 | факты о сцене | понимает сцену без дообучения; открытые веса, работает офлайн; 7B помещается на одну GPU (~0.4 с на кадр); вероятности ответов, а не текст — нет «придуманных» вердиктов |
| OWLv2 (base, patch16, ensemble) | Apache-2.0 | объекты и зоны | ищет «banknotes», «bag», «door» по тексту — не нужна разметка рамок, которой в датасете нет; даёт координаты |

Почему не другое:
- **YOLO / свой детектор** — нужны сотни размеченных рамок; в COCO нет купюр и ключей.
- **Классификатор «видео → нарушение»** — 40 роликов, 1–2 примера на тип: запомнит, а не научится.
- **Одна VLM, оценивающая видео целиком** — проверили: оценка у чистых видео в среднем 0.50, у нарушений
  0.54, точность равна ответу «всегда нарушение».
- **Облачные LLM** — запрещены ТЗ.

## 8. Нормативные источники и сопоставление с видео

Используются только акты Республики Казахстан:

| Документ | Ссылка |
|---|---|
| Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей (Постановление Правления НБРК № 231 от 29.11.2019) | https://adilet.zan.kz/rus/docs/V1900019680 |
| Правила организации охраны и устройства помещений банков (Постановление Правления НБРК № 14 от 24.02.2020) | https://adilet.zan.kz/rus/docs/V2000020075 |

**Принцип сопоставления** (`norms/norms.yaml`, `catalog/violations.yaml`):
1. **Норма** → пункт акта, например № 231, п. 20: принятые деньги хранятся в запирающемся устройстве.
2. **Видимые условия**: А — деньги лежат на столе; Б — кассира нет на месте.
3. **Сигналы**: А проверяет OWLv2 (банкноты сверх фона видео), Б — Qwen («кассир на месте?» → нет).
4. **Правило**: А и Б одновременно ≥ 3 с; **исключения**: кассир рядом, деньги убраны.
5. **Ответ**: тип, таймкод, кадр, документ и пункт, «требуется проверка человеком».

Принципы: то, что требует невидимых данных (сумма, документ, проводка), сервис не утверждает; если
прямой нормы нет, так и пишется, ссылка не выдумывается; у каждой связи «тип → норма» есть статус
(прямая при условиях / условная / косвенная). Подробно: [`docs/NORMATIVE_SOURCES.md`](docs/NORMATIVE_SOURCES.md).

## 9. Типы нарушений

Распознаются автоматически (8 типов):

| Тип | Что должно быть видно | Норма |
|---|---|---|
| Оставление наличных денег без присмотра | наличные на столе ≥ 3 с, кассир отошёл | № 231, п. 20 |
| Деньги предыдущего клиента остаются на столе при новой операции | подходит следующий клиент, а наличные уже лежат на столе | № 231, п. 20 |
| Пересчёт принимаемых наличных в отсутствие клиента | клиент ушёл, кассир держит / пересчитывает наличные | № 231, п. 20 |
| Хранение личных вещей в кассовой зоне | сумка / личная вещь на кассовом столе ≥ 6 с | № 231, п. 12 |
| Употребление кофе над банкнотами на столе | чашка / напиток на кассовом столе ≥ 2 с | прямого пункта нет (риск порчи банкнот) |
| Ненадлежащее хранение инкассаторской сумки | инкассатор ушёл, сумка лежит, у стола никого ≥ 3 с | № 231, п. 93 (косвенно) |
| Проникновение клиента в служебную кассовую зону | посторонний на стороне кассира ≥ 2 с | № 14, п. 8 |
| Оставление служебной двери кассового узла открытой | дверь открыта, пока работают; или область двери в конце видео не как в начале | № 14, п. 8 |

Ещё 9 типов есть в справочнике, но не выставляются: при разрешении 464×848 не видны ключ в замке, дверца
сейфа, экран, суммы, документы, номиналы. Подробно: [`docs/VIOLATION_TYPES.md`](docs/VIOLATION_TYPES.md).

## 10. Качество

Оценка **leave-one-video-out** на 40 размеченных видео (21 с нарушением, 19 чистых): каждое видео
проверяется порогами, посчитанными **без него** — так же, как сервис встретит новые видео.

| Подход | Accuracy | Найдено | Ложные |
|---|---|---|---|
| Ответ «всегда нарушение» (база) | 52 % | 21 / 21 | 19 / 19 |
| Qwen оценивает всё видео целиком | 52 % | 19 / 21 | 17 / 19 |
| State engine, среднее за окно | 62 % | 9 / 21 | 3 / 19 |
| State engine, минимум за окно | 68 % | 8 / 21 | 0 / 19 |
| **+ проверка двери (финал)** | **72 %** | **11 / 21** | **1 / 19** |

## 11. Ограничения и известные ошибки

- При 464×848 не различаются суммы, документы, номиналы, ключ в замке, экран терминала — такие нарушения
  пропускаются (7 из 10 пропусков на обучающих видео).
- Нарушение найдено, тип другой: визит инкассатора → «наличные без присмотра» (X-13); сумка инкассатора →
  «личные вещи» (X-15).
- Ложное срабатывание: чашка на столе в первые секунды видео (X-43).
- Таймкод может быть на 1–4 с позже начала события (кадры раз в секунду).
- Другой угол камеры: сигналы относительные, зоны ищутся заново в каждом видео, но возможны и пропуски,
  и ложные срабатывания.
- Типы, которых не было в обучающих данных, не распознаются.
- Видео обрабатываются по очереди: при одновременной загрузке многих длинных видео время ожидания суммируется.
- Лица не распознаются и не идентифицируются; звук не используется.

Подробно: [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md).

## 13. Пересчёт порогов и тесты

Только на размеченных обучающих видео (`data/videos`, `data/labels.csv`):
```powershell
python forte.py predict --videos data/videos --extract-only   # извлечь признаки (кэш в eval/cache)
python forte.py accuracy                                      # leave-one-out оценка
python forte.py accuracy --write                              # записать пороги для сервиса
python forte.py report --video X-26                           # разбор одного видео
```
Тесты: `python -m pytest -q tests`.
